### 4.8 Decisions and open risks

| # | What we chose not to change or run | Why | Safeguard we propose | Still unresolved |
|---|---|---|---|---|
| 1 | **Historical data not corrected.** These records are still wrong: CSV-imported adjustments posted 10x too small (13); paid batches rewritten by MDR recalculation, e.g. Delta Marketplace −41.870 BD on 11 Sep (16); scheme rounding residue never posted for past months (50; March sweep also wrong, 49); test merchants flipped live and paid out (09); duplicate payout disbursements (24); the CSV applied twice (20). | We did not run corrections on any database. A finance correction needs the owner's approval and should come from source records (e.g. `adjustment_import_rows.raw_amount_text`, the audit log). | Read-only queries first to size each error. Then posted, reviewed correction entries (never edits to past rows), signed off by finance. | Yes. Past ledgers and payouts are still wrong until finance acts. |
| 2 | **ADR-0005 violation left in place.** Migrations 0054-0056 reuse numbers reserved for settlement v2. | `db/migrate.ts` tracks applied migrations by filename. Renaming would re-run them on existing databases. We only neutralised the broken statements in 0054/0055 (bug 01), and every new migration starts at 0073. | Move to a migration table with checksums, then free the reserved range in a planned change. | Yes. Settlement v2 can't use 0054-0056 yet. |
| 3 | **ADR-0007 proposed, superseding ADR-0004.** The console balance rebuild now reads the ledger (bug 39). | ADR-0004's own stated result ("they agree") was false. The brief says the CLI rebuild is correct. | Owner signs off ADR-0007. | Needs owner sign-off. |
| 4 | **Judgement call on bug 56.** Credits post ledger rows at `now()`, and future dates are rejected. | HANDOVER and ARCHITECTURE:39 disagree. We followed HANDOVER because it keeps reconciled periods closed. | Owner confirms the rule, and an ADR records it. | Needs owner decision. |
| 5 | **Capture ignores hold expiry.** Observation only, not changed. | No ADR or brief rule says what should happen. Changing it could block valid captures. | Product decides the rule, then a test and a fix. | Yes. |
| 6 | **Repo integrity.** Commit 098c2de is forged under a departed developer's name. Commit 0af74f0 is backdated. | Git author fields are not authenticated. We can report this but can't fix history. | Signed commits, branch protection, required review. | Yes. Process change for the owner. |
| 7 | **Per-service database roles skipped.** All services connect as one superuser. Load-shed threshold not tuned. | Time. Neither affects correctness today. | One least-privilege role per service. Tune the shed threshold from live measurements. | Yes. |
| 8 | **Hosted demo shows the OTP in login responses on purpose** (`OTP_DEV_EXPOSE=true`). | This lets judges log in without an SMS gateway. The box is a sandbox with no real merchants or money. Seed passwords are generated per deployment (bug 76) and shared privately. | Production **must** set `OTP_DEV_EXPOSE=false`. Login should be a separate, explicit switch, never tied to dev mode (bug 68). | The risk lasts while the demo is up. Turn it off after judging. |
| 9 | **Live database holds ~60k load-test payment links** under "Load Test Merchant". | Left in place as evidence for the capacity figures. | Delete them, or reseed, after judging. Never load-test against a production database. | Yes. Cleanup is pending. |
| 10 | **Settlement redeploy during the midnight close window.** A redeploy could interrupt a close. | Bug 40 fixed the case where a later close quietly skipped captures. Mitigated: a graceful stop period (`stop_grace_period`) and a deploy guard that refuses to deploy during the close window are being added. | Keep the guard. Alert if a close is still unfinished after the window. | Mitigated, not removed. |
| 11 | **No backups off the box.** A nightly `pg_dump` keeps 7 copies on the same machine. | Fine for a demo. Not enough for production. | Encrypted copies off the box, plus a restore drill. | Yes. If the disk is lost, every backup is lost with it. |
| 12 | **Capacity ceiling on a 1 vCPU box.** About 20 checkouts per second sustained, 21 at peak. Above that, requests get a fast 503. The limit is the 20-connection pool held through the acquirer call, and the single vCPU is next. | Measured live. The indexes added for bug 75 doubled throughput. We kept the pool and shed threshold that never produced errors. | Release the connection during the acquirer call, then a bigger box or a separate database host. | Yes. Growth needs both. |
| 13 | **Evidence suggests production may run a different build.** The admin audit CSV shows support accounts doing finance-only actions that this code refuses (403). | We can't see production. | Confirm the deployed commit matches `main` before rollout. | Yes. Needs the owner to check. |
